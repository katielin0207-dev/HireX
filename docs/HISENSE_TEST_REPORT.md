# 海信招聘智能体测试报告与简历包说明

## 1. 业务场景

本轮测试建议聚焦“海信容声（广东）冰箱有限公司 - 现场工艺工程师/制造技术类”。

选择这个岗位的原因：

- 它贴近海信容声真实业务，不是泛泛的软件岗。
- 它能覆盖招聘智能体的关键价值：硬条件筛选、现场经验判断、风险识别、面试核验、人才对比。
- 它适合做 Demo：候选人之间差异明显，容易让评委看懂 AI Agent 的作用。

## 2. 岗位族理解

从海信招聘信息看，海信招聘并不只招单一技术岗位，而是覆盖完整产业链：

- 研发技术类：软件算法、硬件研发、光学显示、芯片、结构、暖通制冷等。
- 制造技术类：现场工艺、IE、设备、质量、生产制造。
- 供应链管理类：采购、计划、仓储物流。
- 营销与运营类：国内/海外营销、产品培训、运营支持。
- 职能类：财务、人力、法务、综合管理等。

对 HireX 来说，最适合先演示的是“制造技术类/现场工艺工程师”，因为这个岗位的筛选标准不是只看学校和技能关键词，而是要判断候选人是否真的有现场经验、问题闭环能力和一线适应性。

## 5. 我反驳一下我们现在的方案

目前没有做好的地方：

1. 岗位理解还偏“通用招聘系统”，不够海信业务化。  
   海信容声的制造岗位很看重一线现场、倒班接受度、质量闭环、跨部门协同，这些不能只靠关键词匹配。

2. 简历筛选的评分容易显得“很像 AI 生成”。  
   如果每个候选人只是 80、70、60 分，评委不会感受到业务价值。需要明确展示“为什么推进/为什么不推进”的证据。

3. 风险识别不能只说“高风险”。  
   HR 真正需要的是：风险是什么、证据在哪里、下一轮面试怎么核验、是否一票否决。

4. 面试评价如果只是总结，会显得像会议纪要工具。  
   必须自动填招聘评价表：结论、维度分、关注点、推荐动作，这才是减少 HR 工作量。

5. 人才对比页必须做出“决策感”。  
   不只是表格，而是告诉用人部门：首选是谁、备选是谁、如果首选放弃 offer 下一位推谁。

6. 当前产品还没有体现“接入北森/内部系统”的边界。  
   Demo 里要说清楚：HireX 不替代 ATS，而是作为 AI Agent 层接在流程上方，输出结构化评价和推荐。

## 6. Demo 话术建议

一句话开场：

> 我们不是再做一个招聘网站，而是在企业现有招聘系统上方加一个 AI 招聘甄选 Agent，让 HR 和用人部门少做重复判断，把时间花在关键候选人确认上。

演示重点：

1. 先展示海信容声现场工艺工程师 JD。
2. 展示 6 个候选人的差异，不要只展示一个人。
3. 点开周明远风险报告，突出经历断层和证书过期。
4. 点开林嘉豪面试评价，展示自动填写评价表。
5. 最后说：如果首选候选人放弃 offer，系统会推备选候选人，减少复盘成本。
